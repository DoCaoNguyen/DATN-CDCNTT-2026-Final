================================================================================
      TÀI LIỆU TÍCH HỢP CỔNG THANH TOÁN (MERCHANT API & WEBHOOK)
================================================================================

Tài liệu này cung cấp hướng dẫn chi tiết để đội ngũ phát triển (hoặc AI) của App Tích Điểm (đóng vai trò là Merchant) có thể tích hợp với Cổng Thanh Toán của Ví Điện Tử.

Mô hình hoạt động (Flow):
1. User chọn mua hàng/tích điểm trên App Merchant.
2. App Merchant gọi API "Tạo đơn hàng thanh toán" sang Server Ví.
3. Server Ví trả về một mã QR (qr_token) hoặc link thanh toán.
4. App Merchant hiển thị mã QR này cho User quét bằng App Ví Điện Tử (hoặc link deep-link).
5. User thực hiện thanh toán thành công trên App Ví.
6. Server Ví gửi một yêu cầu HTTP POST (Webhook) ngầm về Server Merchant để thông báo trạng thái thành công.
7. Server Merchant xác thực chữ ký (Signature) của Webhook, cộng điểm cho User và trả về HTTP 200 OK.

--------------------------------------------------------------------------------
PHẦN 1: KẾT NỐI VÀ XÁC THỰC (AUTHENTICATION)
--------------------------------------------------------------------------------
Để có thể gọi API và nhận Webhook, Merchant cần liên hệ Admin Ví để được cấp 2 thông tin:
1. `API_KEY`: Dùng để gắn vào header khi gọi API tạo đơn hàng.
2. `SECRET_KEY`: Dùng để giải mã/xác thực chữ ký của Webhook gửi về.

--------------------------------------------------------------------------------
PHẦN 2: API TẠO ĐƠN HÀNG THANH TOÁN
--------------------------------------------------------------------------------
App Merchant gọi API này để tạo một mã yêu cầu thanh toán.

- Endpoint: `POST /api/v1/payment/create`
- Headers:
    + `Content-Type: application/json`
    + `x-api-key: <API_KEY_CỦA_MERCHANT>`

- Body (JSON):
{
    "amount": 50000, 
    "callback_url": "https://merchant-domain.com/api/webhook-receive", 
    "description": "Thanh toán đơn hàng TichDiem_123"
}
* Lưu ý: `callback_url` là đường dẫn API của Merchant để Server Ví gọi về khi thanh toán xong.

- Response Thành Công (HTTP 201):
{
    "message": "Tạo đơn hàng thanh toán thành công",
    "data": {
        "order_id": "ORD-ABC-XYZ",
        "qr_token": "chuoi-token-qr-code"
    }
}
* Merchant dùng `qr_token` để render ra ảnh QR Code cho User quét.

--------------------------------------------------------------------------------
PHẦN 3: WEBHOOK NHẬN KẾT QUẢ THANH TOÁN (QUAN TRỌNG NHẤT)
--------------------------------------------------------------------------------
Khi User thanh toán xong, Server Ví sẽ gọi API (`callback_url`) của Merchant. 

1. ĐỊNH DẠNG WEBHOOK:
- Method: `POST`
- Headers nổi bật:
    + `content-type: application/json`
    + `x-webhook-signature`: Chuỗi mã hóa HMAC SHA256 để bảo mật.

- Body (JSON):
{
  "order_id": "ORD-ABC-XYZ",
  "status": "success",
  "amount": "50000",
  "wallet_transaction_id": "uuid-cua-giao-dich"
}

2. THUẬT TOÁN XÁC THỰC CHỮ KÝ (HMAC SHA256):
Để đảm bảo request thực sự đến từ Server Ví (không bị hacker giả mạo để cộng khống điểm), Merchant BẮT BUỘC phải kiểm tra chữ ký ở header `x-webhook-signature`.

* Thuật toán: 
  signature = HMAC_SHA256(secret_key, raw_body_json)

* Code mẫu bằng Node.js cho Merchant:
```javascript
const crypto = require('crypto');
const express = require('express');
const app = express();

const MERCHANT_SECRET_KEY = "SECRET_KEY_DUOC_CAP";

// Quan trọng: Phải lấy được chuỗi JSON raw gốc để hash không bị sai lệch
app.post('/api/webhook-receive', express.json(), (req, res) => {
    const receivedSignature = req.headers['x-webhook-signature'];
    const payloadString = JSON.stringify(req.body);

    // Băm lại payload theo chuẩn HMAC SHA256
    const expectedSignature = crypto
        .createHmac('sha256', MERCHANT_SECRET_KEY)
        .update(payloadString)
        .digest('hex');

    if (receivedSignature === expectedSignature) {
        // XÁC THỰC THÀNH CÔNG: Chắc chắn request gửi từ Server Ví
        const data = req.body;
        if (data.status === 'success') {
            // TODO: Cộng điểm cho User, cập nhật trạng thái đơn hàng...
            console.log("Cộng điểm thành công cho đơn:", data.order_id);
        }
        
        // Bắt buộc phải trả về HTTP Status 200 để Server Ví biết đã nhận được
        return res.status(200).json({ message: 'OK' });
    } else {
        // XÁC THỰC THẤT BẠI: Đây có thể là request giả mạo
        return res.status(403).json({ message: 'Invalid Signature' });
    }
});
```

3. CƠ CHẾ RETRY (GỌI LẠI KHI LỖI):
Nếu Server Merchant bị sập, timeout, hoặc trả về HTTP Status khác `2xx` (ví dụ 500, 404), Server Ví Điện Tử sẽ đưa Webhook vào hàng đợi (Queue) và TỰ ĐỘNG GỌI LẠI nhiều lần với thời gian chờ tăng dần (Backoff) cho đến khi Merchant trả về `200 OK`. 
Do đó, Merchant cần thiết kế hàm nhận Webhook có tính chất *Idempotent* (nếu nhận 1 webhook 2 lần thì chỉ cộng điểm 1 lần dựa vào `order_id`).
